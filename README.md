> 수백 년 검증된 **고전 이야기의 뼈대**를, 아직 아무도 안 넣어본 **현대 세팅**에 이식해 —
> 신선하되 말 되는 이야기 프리미스를 **"진짜 덜 쓰였다"는 실데이터 근거**와 함께 뽑아준다.

design-explosion의 **스토리판**. "AI가 이야기를 대신 쓴다"가 아니라, 실제 이야기를 **세어서** 조준하는 분석 도구.
**매칭은 결정적(코드·취향 0), 융합만 창작(LLM).**

## 한눈에 — 세팅 하나 → 피칭 패킷

작가가 `아이돌 기획사`만 던지면, 도구가 이런 패킷을 뽑는다:

```
프리미스 : 창립 센터가 '자진 탈퇴'로 밀려난 뒤, 그 자리를 꿰찬 멤버가 팀을 독식한다.
           원조 센터의 동생(신인)이 삭제됐어야 할 녹취에서 퇴출 조작을 알아채지만 —
           폭로하면 그룹이 죽어 망설이다, 컴백 무대에서 모든 게 터진다.
comp    : 햄릿 meets 아이돌 서바이벌
로그라인 : 형의 자리를 뺏은 센터에게 복수하려는 신인이, 그 망설임으로 팀을 무너뜨린다.
근거    : 뼈대 검증 33 · 궁정→아이돌 이식 신선 · 요구 2/2 충족(G3·G9) · 이 세팅 1등 매칭
```

> **"햄릿을 아이돌에 이식했다."** 검증된 구조 위라 백지보다 낫고, 아무도 안 한 조합이라 신선하고,
> **왜 신선한지 숫자로 증명**된다. → [「센터」 웹툰으로 보기](https://deokjinlog.github.io/classic-bones-modern-fusion/)

## 어떻게 — 3층 × 파이프라인

| 층 | 뭐냐 | 출처 |
|---|---|---|
| **뼈대** | 이야기의 구조 = 엔진·역할·턴 (찬탈복수 = 햄릿형) | WikiPlots에서 추출 |
| **스키마** | 뼈대가 *요구하는 조건*의 공통 어휘 (27) | 실제 이야기에서 **도출** |
| **세팅** | 이식할 현대 무대 (스타트업·병원·아이돌…) | 큐레이션 + 도메인 사실로 태깅 |

```
세팅 선택 ─▶ 매칭(요구 ⊆ 보유, 코드) ─▶ 융합(LLM) ─▶ 프리미스 + 근거
```
- **매칭 = 취향 0** — 겹침 세기(집합연산)라 재현·검수 가능. 점수 = 신선도 × 검증도.
- **융합만 창작** — 뼈대가 구조를 고정하니 "통제된 창의".
- **스키마는 "내용물"이 아니라 "조건"** — `왕·검·궁정`(표면)이 아니라 `뺏을 권좌·밝혀질 살인`(옮겨지는 조건)만.

## 왜 데이터인가 — GPT가 못 하는 한 가지

GPT에 "신선한 이야기 줘" 하면 제일 흔한 **클리셰로 회귀**한다 — 학습을 빈번한 것으로 압축해 *부재*를 잃기 때문. 이 도구는 실제 이야기를 **세어서** "이 조합이 진짜 덜 쓰였다"를 증명한다. **가치는 프리미스가 아니라 근거.** (시장 리서치: "신선하되 익숙"이 할리우드·출판·웹소설의 중심논리이고, 그 *근거*를 대주는 도구는 아직 없었음.)

## 써보기

프로젝트 폴더에서 스킬 **`classic-bones-fusion`** 호출 → 세팅 하나 던지면 매칭→융합→패킷.
```bash
python3 src/match.py 아이돌기획사   # 매칭만 미리 보기 (뼈대 순위)
```
현재 규모: **뼈대 23종 · 세팅 27종 · 스키마 27속성** — 전부 실데이터 도출.
