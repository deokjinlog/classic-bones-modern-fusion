# classic-bones-fusion

**검증된 고전 뼈대 × 아직 아무도 안 넣어본 현대 세팅 = 신선한 프리미스.**
매칭은 결정적(코드·취향 0), 융합만 창작(LLM). 값어치는 프리미스가 아니라 **영수증**(왜 신선한지 숫자).

## 언제 쓰나
사용자가 현대 세팅(스타트업·병원·아이돌…)이나 고전 뼈대를 주고 "이걸로 이야기/프리미스 뽑아줘", "이 세팅에 맞는 고전 구조 찾아줘" 할 때.

## 실행 — 5단계

### ① 세팅 확정 (가이드된 자유)
- `data/settings.json`의 메뉴를 보여주고 고르게 하거나, 사용자가 **자유 입력**.
- 자유 입력이면 → `docs/schema.md`의 **하드게이트 코드(G1~G21)** 로 그 세팅의 *보유 조건*을 태깅(도메인 사실 근거로, 사람 검수 가능하게). 예: 스타트업 → G1 지분서열·G3 이사회 승계·G9 회계은폐·G13 압박…
- 사용자가 뭘 쓸지 모르면 **"놀래줘"**: 구조 풍부한 세팅 몇 개 제안.

### ② 매칭 (결정적·코드)
메뉴 세팅이면:
```
python3 src/match.py <세팅키>
```
자유 세팅이면 같은 규칙을 손으로: 각 뼈대의 `req` ⊆ 세팅 `보유` 인지 세고,
**점수 = 신선도(1−modern_done) × 검증도(proven = freq + 8×canon_freq)**. 완전 적합만 후보, 점수순.

### ③ 상위 뼈대 선정
1등(또는 사용자가 고른 것)만 융합. **에디터형**: 약한 세팅을 우겨도 만들되 영수증에 품질 투명하게(`충족 1/n`), 거절 대신 살 붙여 보강 제안.

### ④ 융합 (창작·LLM)
뼈대의 `roles`·`turns`를 세팅 재료로 **1:1 매핑**:
- 각 역할 → 세팅의 대응 인물/요소 (예: [죽은 권력자]→쫓겨난 창업 CEO)
- 각 턴 → 세팅에서 벌어지는 사건 (예: 살해·찬탈→이사회 쿠데타)
- **표면은 버리고 구조만 이식.** 뻔한 트로프 조합은 피함.

### ⑤ 출력 = 피칭 패킷
```
프리미스 : (2~3문장, 구체적으로)
comp    : <뼈대 대표작> meets <세팅>
로그라인 : (한 문장 후크)
영수증   : 검증(proven=freq+캐논) · 신선(modern_done·집 home→세팅 거리) · 양립(요구 n/n 충족: 코드) · 순위
뼈대     : <원형> — 역할·턴
```
(선택) 결과를 `exhibits/`에 웹툰 스타일 정적 HTML로 만들어 아티팩트로 배포 가능.

## 원칙
1. **매칭은 취향 0** — 요구⊆보유 겹침 세기. 재현·검수 가능. "느낌"으로 순위 안 바꿈.
2. **융합만 창작** — 뼈대가 구조를 고정하니 통제된 창의.
3. **영수증 필수** — 신선·검증·양립 숫자 없이 프리미스만 내지 않음.
4. **뻔하면 자동 후순위**(신선도↓), **안 맞으면 자동 탈락**(요구 불충족).

## 데이터 파일 (프로젝트 루트 기준)

- `data/settings.json` — 현대 세팅 + 보유 하드게이트 코드
- `docs/schema.md` — 27속성 스키마 (하드게이트 21로 매칭)
- `src/match.py` — 결정적 매칭 엔진
- `docs/art-prompts.md` — 웹툰 작화용 이미지 프롬프트 (선택)
